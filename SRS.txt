1. INTRODUCTION
------------------------------------------------------------------------------
1.1 Purpose
The purpose of this Software Requirements Specification (SRS) is to define the 
functional and non-functional requirements of the Amber Cast (Handcrafted BrassCraft) 
Online Atelier Website, developed using Python Django.
The system is designed to provide a luxury online platform where collectors and 
patrons can browse, search, inspect, and purchase handcrafted brass metal products 
such as sacred deity idols (Nataraja, Ganesha, Krishna, Saraswati), traditional 
oil lamps (Kuthu Vilakku, Gaja Lakshmi Diya), temple hanging bells, bell-metal 
urulis, and architectural fittings.

1.2 Document Conventions
- SRS   : Software Requirements Specification
- Admin : Store & Foundry Workshop Administrator (Atelier Guildmaster)
- Patron/User : Registered Customer or Collector
- System : Amber Cast Web Application
- Ingot/Product : Handcrafted solid brass metal items forged via Cire-Perdue (Lost-Wax)
- COD   : Cash On Delivery physical settlement upon unboxing inspection
- Online Payment : Instant electronic escrow / digital gateway settlement

1.3 Intended Audience
- Project Managers
- Full-Stack Developers & System Architects
- Quality Assurance / Testers
- Database Administrators
- Artisanal Foundry Administrators & Curators

1.4 Project Scope
The Amber Cast system is a full-featured web-based e-commerce and workshop 
governance application built on Django's Model-View-Template (MVT) architecture.
The platform enables customers to:
- Browse collections filtered by category, mass (weight), surface patina, and price
- Conduct multi-field searches across product titles, descriptions, and alloys
- Inspect metallurgical spec sheets (composition, weight, dimensions, technique, provenance)
- Add artworks to an active session curation bag
- Place orders through Cash on Delivery (COD) or simulated online escrow
- Receive serialized Commission Certificates with verifiable order references
- Write and view authentic collector reviews with star ratings

The administrator / workshop console allows the guild to:
- Monitor gross revenue, active commissions, critical stock alerts, and patron metrics
- Inspect and update the master Ingot Inventory table with real-time "+5 Smelt" restock
- Progress order fulfillment stages (Processing -> Shipped -> Delivered)
- Mint new brass casting products into the catalog with live preview
- Track furnace smelting telemetry and material reserves

2. OVERALL DESCRIPTION
==============================================================================
2.1 Product Perspective
Amber Cast operates as an autonomous, self-contained Django web application.
It integrates relational database persistence (SQLite for local development, 
readily upgradable to PostgreSQL/MySQL in production), dynamic template rendering, 
and responsive Tailwind design system tokens mimicking burnished brass, raw amber, 
and warm parchment.

2.2 Core Product Features
1. User Management (Registration, Authentication, Profile & Address Book)
2. Product Catalog & Multi-Attribute Search & Filter
3. Metallurgical Spec Sheet & Inspection Flyout Drawer
4. Shopping Cart & Quantity Counter Synchronization
5. Two-Tier Checkout (Digital Escrow vs Cash On Delivery)
6. Automated Stock & Inventory Decrement upon Order
7. Patron Order Tracking & Historical Commission Dossier
8. Commission Certificate Generation & Print Capabilities
9. Verified Collector Reviews & 5-Star Rating System
10. Atelier Workshop Console (Inventory, Restock, Orders, Telemetry, New Mint)

2.3 User Classes and Characteristics
- Customer / Patron:
  * Register and authenticate via unique email address
  * Maintain delivery addresses and contact information
  * Browse and search heirloom statues and ceremonial vessels
  * Add items to curation bag with live tax and discount token calculations
  * Complete checkout with COD or digital payment
  * Review order history and inspect individual commission certificates
  * Post reviews on acquired artworks

- Atelier Administrator / Guildmaster:
  * Full access to Django standard administration (/admin/)
  * Access to dedicated Atelier Management Dashboard (/atelier/)
  * Update order fulfillment stages in real time
  * Trigger immediate furnace smelt restocks (+5 units)
  * Mint new brass casting records with metallurgical specifications
  * View aggregate fiscal telemetry and category distribution

2.4 Operating Environment
- Operating System : macOS, Linux, or Windows 10/11
- Runtime          : Python 3.10+ (tested on Python 3.14)
- Web Framework    : Django 6.1+
- Database         : SQLite 3 / MySQL / PostgreSQL
- Web Browsers     : Google Chrome, Mozilla Firefox, Apple Safari, Microsoft Edge

2.5 Design and Implementation Constraints
- Django MVT architectural pattern
- Strict CSRF protection on all mutating POST endpoints
- Unique email constraint for patron accounts
- Safe integer quantity updates to prevent negative stock counts
- Responsive fluid grid supporting mobile (375px+), tablet (768px+), and desktop (1280px+)

3. SYSTEM DATABASE DESIGN & TABLES
==============================================================================
The database schema strictly adheres to the System Design specifications:

TABLE 1: store_user (Custom User Model)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------
id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of the user
first_name       | VARCHAR(100) | NOT NULL                     | User's first name
last_name        | VARCHAR(100) | NOT NULL                     | User's last name
email            | VARCHAR(150) | UNIQUE, NOT NULL             | Email used for login
password         | VARCHAR(255) | NOT NULL                     | PBKDF2/SHA-256 hashed pwd
phone            | VARCHAR(20)  | NULL, BLANK                  | Contact phone number
address          | TEXT         | NULL, BLANK                  | Default delivery address
role             | VARCHAR(20)  | NOT NULL, DEFAULT 'Customer' | 'Customer' or 'Admin'
is_staff         | BOOLEAN      | DEFAULT FALSE                | Admin console access flag
is_active        | BOOLEAN      | DEFAULT TRUE                 | Account active status
date_joined      | DATETIME     | NOT NULL                     | Inscription timestamp

TABLE 2: store_product (Artisanal Brass Artifacts)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------
id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of the product
product_name     | VARCHAR(150) | NOT NULL                     | Handcrafted artwork name
sku              | VARCHAR(50)  | UNIQUE, NOT NULL             | Guild inventory SKU code
category         | VARCHAR(100) | NOT NULL                     | Deities, Diyas, Urulis, etc.
description      | TEXT         | NOT NULL                     | Iconography & history text
price            | DECIMAL(10,2)| NOT NULL                     | Selling price in USD
original_price   | DECIMAL(10,2)| NULL, BLANK                  | Pre-privilege retail price
stock_quantity   | INT          | NOT NULL, DEFAULT 0          | Current available units
is_available     | BOOLEAN      | DEFAULT TRUE                 | Purchase eligibility flag
weight           | VARCHAR(50)  | DEFAULT '3.5 kg'             | Physical weight spec
dimensions       | VARCHAR(100) | DEFAULT '14" x 10"'          | Height x Width dimensions
alloy_blend      | VARCHAR(120) | NOT NULL                     | Metallurgy alloy blend
patina_finish    | VARCHAR(100) | NOT NULL                     | Antique Ochre, Polished, etc.
casting_technique| VARCHAR(120) | NOT NULL                     | Cire-Perdue, Sand Cast, etc.
provenance       | VARCHAR(150) | NOT NULL                     | Sthapati collective guild
is_featured      | BOOLEAN      | DEFAULT FALSE                | Hero showcase flag
created_at       | DATETIME     | AUTO_NOW_ADD                 | Creation timestamp

TABLE 3: store_productimage (Product Photography & Renderings)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------
id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of the image
product_id       | INT (FK)     | REFERENCES store_product(id) | Target product relation
image_path       | VARCHAR(500) | NOT NULL                     | Stored image path or URL
is_primary       | BOOLEAN      | DEFAULT FALSE                | Primary thumbnail flag

TABLE 4: store_cart (User Shopping Cart)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------

user_id          | INT (FK, UQ) | REFERENCES store_user(id)    | 1:1 active cart per user

TABLE 5: store_cartitem (Cart Line Items)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------
id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of the cart item

quantity         | INT          | NOT NULL, DEFAULT 1          | Number of pieces

Field Name       | Data Type    | Constraints                  | Description

id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of the order
order_reference  | VARCHAR(50)  | UNIQUE, NOT NULL             | Reference e.g. #ORD-9801

TABLE 7: store_orderitem (Order Line Items)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description

id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of the order item
order_id         | INT (FK)     | REFERENCES store_order(id)   | Parent order relation

Field Name       | Data Type    | Constraints                  | Description

TABLE 9: store_inventory (Foundry Ingot Stock Sync)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------
id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of inventory
product_id       | INT (FK, UQ) | REFERENCES store_product(id) | 1:1 product stock record
quantity_available| INT         | NOT NULL, DEFAULT 0          | Current physical pieces
last_updated     | DATETIME     | AUTO_NOW                     | Last smelt update time

TABLE 10: store_review (Collector Testimonials)
------------------------------------------------------------------------------
Field Name       | Data Type    | Constraints                  | Description
-----------------+--------------+------------------------------+---------------------------
id               | INT (PK)     | AUTO_INCREMENT               | Unique ID of review
user_id          | INT (FK)     | REFERENCES store_user(id)    | Reviewing patron
product_id       | INT (FK)     | REFERENCES store_product(id) | Target artwork
rating           | INT          | NOT NULL (1 to 5)            | Star score (1-5)
comment          | TEXT         | NULL, BLANK                  | Review commentary text
created_at       | DATETIME     | AUTO_NOW_ADD                 | Review post timestamp

TABLE RELATIONSHIPS
------------------------------------------------------------------------------
- User 1 : 1 Cart (Each user has one persistent curation bag)
- Cart 1 : N CartItem
- Product 1 : N CartItem
- User 1 : N Order (One patron can place multiple commissions)
- Order 1 : N OrderItem
- Product 1 : N OrderItem
- Order 1 : 1 Payment (Each order is tied to one payment record)
- Product 1 : 1 Inventory (Each product has a synchronized inventory record)
- Product 1 : N ProductImage (Multiple detail angles per casting)
- Product 1 : N Review (Multiple patron evaluations per piece)
- User 1 : N Review

5. HOW TO RUN THE PROJECT LOCALLY
==============================================================================
Step 1: Ensure Python 3.10+ is installed.
Step 2: Install required packages:
        pip install django pillow

Step 3: Apply migrations:
        python manage.py makemigrations
        python manage.py migrate

Step 4: Seed pre-populated database with 14 artisanal brass castings, sample orders,
        reviews, and default user accounts:
        python manage.py seed_data

Step 5: Run the development server:
        python manage.py runserver

Step 6: Open http://127.0.0.1:8000 in your browser.
